# Security and maintenance follow-up — November 2, 2026

This follow-up keeps Magpet fixed to one branch and preserves sales, cash, stock and pending records. No paid plan, trial, subscription, secret rotation or production promotion is authorized by the changes below.

## Implemented protections

- The static app sends a Content Security Policy limiting scripts/assets to its own origin, connections to its configured Supabase origin, workers/manifests to its own origin, and prohibiting plugins, base-tag changes, foreign form posts and framing. HTTPS persistence and restrictions on unused camera, microphone, location and payment APIs are added. Existing anti-framing, MIME and referrer protections remain.
- Next's inline bootstrap and the current receipt/chart styles still require inline permission. This is a baseline policy, **not** a strict nonce-based CSP or a claim that all injection is impossible. Changing rendering/cached-shell strategy requires a separately tested design; the PWA must keep working offline.
- Twelve private command-only tables receive explicit restrictive client-deny policies. Their previous implicit default-deny behavior remains, and an accidentally added permissive policy cannot override it. Table ownership, RLS mode and grants remain unchanged. Session/role/branch-authorized commands continue to read/write through their existing private owners.
- Verified current Node 24 GitHub actions are pinned to full commit IDs. Checkout no longer persists a repository credential. Existing read-only job permissions and disposable database credentials remain.
- Every full code gate now rejects any production dependency advisory and any high/critical advisory across the dependency tree. Remaining lower-severity build findings are printed, not suppressed. Weekly Dependabot proposals cover packages and actions; proposals require review and passing tests before merging, with no automatic deployment/merge added.

## Dependency changes and remaining warnings

Next and its matching lint configuration move from 16.4.2 to the 16.4.3 patch. Workbox's build dependency moves to the monorepo root so the reviewed root override is actually honored. Its compatible modern glob API is pinned to patched 14.0.3; modern minimatch consumers use 11.0.1. Legacy minimatch consumers are not forced onto an incompatible export/API shape.

The full audit decreases from **24 to 22 findings: two low and twenty moderate, all in build/development tools; zero high/critical and zero production dependency advisories**. Remaining roots are [deepmerge, which currently has no published patched version](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), and [minimatch advisories affecting legacy build-tool dependencies](https://github.com/advisories/GHSA-g3hv-75wg-m249). The [patched glob advisory](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) is removed. The lockfile retains exact resolved versions and integrity hashes.

ESLint 9 remains because the current React/import/accessibility plugins do not declare ESLint 10 compatibility. The registry's suggested force-fix would downgrade major tools, so it is not used. Supported compatible upstream updates still need maintainer review; zero production advisories is not a promise of zero security risk.
