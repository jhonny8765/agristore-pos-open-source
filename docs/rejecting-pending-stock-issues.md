# Reject a mistaken stock-issue request

Use this when a damage, spillage or other stock request is **still pending** and was entered incorrectly. Only an online owner can reject it. Stock staff and cashiers cannot make this decision.

## Check first

1. Open **Inventory**, select the correct branch and choose **Refresh stock controls**.
2. Find the request under **Damage, spillage and other stock issues**. Use **Load more stock issues** if needed.
3. Check the product, lot, measurement, original quantity and reason against the goods and records. For example, **0.125 liter (125 ml)** means 125 ml, not 125 liters. A quarter meter is **0.25 meter**.
4. Decide whether the request is a mistake or a real loss. A missing-stock investigation needs its own evidence and outcome; rejection does not close it.

## Record the rejection

1. Choose **Reject stock issue** for that request.
2. In **Rejection notes**, explain what you checked and why it is mistaken. Example: “Checked the shelf and delivery record. The same damaged container was reported twice; retain the first request.”
3. Choose **Reject request** once. Wait for the recorded result.
4. Find it in **Rejected stock issues** below. The original request, quantity, owner name, decision date, reason and reference IDs remain visible. Newest decisions appear first; **Load more rejected requests** retrieves older decisions.
5. Check that stock, cash and purchase-cost loss totals are unchanged. A rejection approves no stock movement, creates no held goods and values no loss.

The original rejected request cannot be edited, deleted, reopened or approved later. If a corrected request is necessary, create a new request after checking the evidence. An already approved stock issue requires owner reconciliation; this control cannot undo its stock effect.

## If the connection breaks

1. Open **Sync center** and locate the unresolved operation.
2. Sign in as the original owner and choose **Retry original request**. The app reuses the original decision reference, including when the server saved the rejection but its reply was lost.
3. If the PC needs recovery, export its recovery file and keep it private. Restore it as the original employee through the documented recovery procedure, then retry the original request. Do not clear browser data or make another decision to replace an uncertain save.
4. If another owner decided first, refresh stock controls and read the retained result. Approval and rejection cannot both succeed for the same request. A successful approval has its normal stock effect; a successful rejection has none.

Rehearse this with clearly labelled TEST records before real operations. It does not replace independent counts, physical handling checks or daily reconciliation. See [measured stock procedures](measured-units.md) and [purchase-cost loss reports](purchase-cost-loss-reports.md).
