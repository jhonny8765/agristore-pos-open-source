# Download and keep recovery files

Recovery files protect unresolved sales and stock/owner requests. They contain private transaction data; keep them in a protected folder and keep the original browser profile and site data.

1. Open **Sync center** and select **Export recovery file**. The same action is available under **Settings → Application & recovery → Export local recovery file**.
2. Read **Check your recovery download**. It shows the exact filename, part number, number of sale records and number of stock/owner requests in this part. A file with zero sales can still contain requests that need recovery.
3. Open your browser Downloads or the folder you chose, and verify that exact file exists. **Download started** is not proof that Windows saved the file.
4. If the file is missing or blocked, choose **Download this part again**. This repeats the same filename and contents. It does not create a sale, change stock/cash or advance the export. Browsers may add a suffix to a duplicate downloaded filename.
5. For a multipart export, keep the current part before choosing **Export recovery part 2 of 2** (or the next numbered part). Every part is needed. Only the latest prepared part is available for immediate retry; finish keeping it before moving on.
6. New purchases made after an export starts need a new export after the current set is complete. Closing or reloading the app clears the prepared download and next-part screen state; start a fresh export for records still unresolved. Already confirmed transactions remain in local/cloud history.
7. Signing out or changing account/branch clears the prepared download and next-part controls. Re-export from the correct authorized account and branch; sales and requests stay stored for recovery.

If a download remains blocked, preserve the browser/profile, unresolved records and all existing files. Ask the owner to investigate the browser's download notice. Do not clear site data, manufacture another checkout or remove existing recovery files to retry.

Recovery exports contain at most 1,000 sale records per part; requests are included with the first part. An operations-only file may have zero sales and one or more requests. Restore uses the original IDs and normal access checks; it does not turn an old sale into a new purchase. The immediate retry keeps only the latest prepared part in memory and does not change the recovery file format.
